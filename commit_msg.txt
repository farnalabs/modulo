fix(FAR-797): repair generated POSIX credential-provisioning script

The PR Reviewer (farnalabs) flagged that build_provisioning_credential_scripts()
emitted a POSIX script that cannot run (verified via sh -n). Fixes:

- CRED heredoc opener was missing its closing quote (<<'_CRED_EOF_'): the body
  was parsed as a quoted string, breaking command substitution in dash/bash.
- Dropped the malformed `echo 'protocol=https\nhost=...' "| git credential fill`
  line (stray quote + literal backslash-n that never parsed).
- GIT_ASKPASS helper read $_modulo_cred_file, which was never exported, so the
  askpass subprocess returned an empty password. Now export it.
- Teardown referenced mktemp shell vars that vanish when the setup shell exits,
  so it removed nothing. Setup now records the ephemeral paths to a
  uuid-suffixed state file that teardown reads and cleans up.
- Removed `git config --global credential.helper store`, which persisted the
  secret in plaintext at ~/.git-credentials (askpass-only flow keeps it in the
  0600 /dev/shm file and removes it on teardown).
- assert_clone_credential_is_read_only now fails closed on an empty
  X-OAuth-Scopes header (GitHub fine-grained PATs), instead of accepting a
  write-capable fine-grained PAT as read-only.

Adds round-trip shell tests (sh -n parse + real execution in a temp HOME that
asserts the askpass returns the username/password and teardown removes the
files) plus the empty-scope read-only refusal test.
