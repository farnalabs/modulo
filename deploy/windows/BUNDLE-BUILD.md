# Windows native bundle build

`scripts/build-windows-bundle.ps1` assembles the provisioned native bundle directory consumed by `deploy/windows/modulo.iss`. It never creates runtime inputs, a launcher, a release manifest, or a signature. Missing or invalid inputs fail closed.

## Required provisioned inputs

| Bundle path | Input |
|---|---|
| `launcher` | Real native Windows launcher input |
| `runtime` | Windows CPython runtime |
| `pg` | Provisioned Windows PostgreSQL distribution |
| `redis` | Provisioned Windows Redis distribution |
| `bin` | Provisioned native support binaries |
| `frontend-dist` | Built frontend distribution |
| `backend/.venv` | Windows backend virtual environment |
| `RELEASE_MANIFEST.json` | Signed release manifest from the release process |
| `RELEASE_MANIFEST.json.sig` | Signature for that exact manifest |

Redis, Windows CPython/PostgreSQL provenance, and native launcher support remain explicitly blocked when the corresponding inputs are not provisioned. The builder does not invent hashes, URLs, signatures, fake PE files, or replacement runtimes.

## Commands

```powershell
# Check inputs only. No bundle directory or artifact is created.
pwsh scripts/build-windows-bundle.ps1 -Version 0.4.0 -ValidateOnly

# Assemble the exact directory consumed by Inno Setup.
pwsh scripts/build-windows-bundle.ps1 -Version 0.4.0 `
  -LauncherPath C:\provisioned\launcher `
  -RuntimeDirectory C:\provisioned\runtime `
  -PostgresDirectory C:\provisioned\pg `
  -RedisDirectory C:\provisioned\redis `
  -BinDirectory C:\provisioned\bin `
  -FrontendDistDirectory C:\provisioned\frontend-dist `
  -BackendVenvDirectory C:\provisioned\backend\.venv `
  -ReleaseManifestPath C:\release\RELEASE_MANIFEST.json `
  -ReleaseManifestSignaturePath C:\release\RELEASE_MANIFEST.json.sig
```

The same values may be supplied through the `MODULO_WINDOWS_*` environment variables documented by the script. The signed release manifest is verified before assembly and again after copying. Invalid or missing signatures stop the build; no signature is generated by this builder.

The output is a bundle directory, not an installer. Inno Setup receives that directory as `BUNDLE_DIR`, checks the same launcher and signed-manifest handoff, and copies the layout unchanged. The release workflow uploads the resulting `modulo-<VERSION>-windows-amd64.exe` as artifact `windows-installer-<VERSION>`.
